# Partners CRM — визитки через Telegram

Внутренняя CRM на 2 человек для сбора контактов на выставках.
Фото визитки в бот → оригинал сохраняется → GPT vision распознаёт контакты → карточка `#P12`.
Заметки (текст, голосовые, файлы) привязываются ответом (Reply) на визитку или на любое сообщение её цепочки.
Если непонятно, к кому относится сообщение, бот спрашивает «К кому это?».

Стек: Python 3.12, FastAPI, SQLAlchemy, PostgreSQL (фото хранятся в БД), Render.

## Развёртывание на Render

1. **Бот**: в Telegram у @BotFather → `/newbot` → получить токен.
2. **OpenAI**: ключ API на platform.openai.com.
3. **GitHub**: создать приватный репозиторий и запушить этот проект.
4. **Render** → New → Blueprint → выбрать репозиторий. Render прочитает `render.yaml` и создаст веб-сервис и базу. Заполнить:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `TELEGRAM_ALLOWED_IDS` — пока можно `0`, см. п.6;
   - `WEB_USERS` — логины и пароли для сайта: `anna:пароль1,boris:пароль2`;
   - `OPENAI_API_KEY`.
5. После деплоя webhook ставится сам (адрес берётся из `RENDER_EXTERNAL_URL`). Проверка: `https://<сервис>.onrender.com/healthz` → `{"ok":true}`.
6. Каждый из двоих пишет боту `/start` — бот ответит «Доступ закрыт, ваш ID: …». Вписать оба ID через запятую в `TELEGRAM_ALLOWED_IDS` (Render → сервис → Environment → Save) — сервис перезапустится.

## Настройки

| Переменная | Что это |
|---|---|
| `OPENAI_MODEL` | модель распознавания, по умолчанию `gpt-6-luna` |
| `DISPLAY_TZ` | часовой пояс на сайте, по умолчанию `Asia/Tashkent` |
| `PUBLIC_URL` | адрес сайта, если не Render (там берётся автоматически) |

## Локальный запуск и тесты

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
pytest -q                                   # тесты без сети, на SQLite
WEB_USERS=me:pw uvicorn app.main:app --reload   # сайт на http://localhost:8000
```

## Как устроена привязка

Каждое сообщение чата — и пользователя, и бота — записывается в `tg_links` (chat_id + message_id → карточка).
Ответ на любое сообщение находит карточку по этой таблице, поэтому глубина цепочки не ограничена, а параллельные цепочки не смешиваются.
Повторная доставка того же update от Telegram отбрасывается по `update_id`.
Поля, исправленные вручную на сайте, повторное распознавание не перезаписывает.
